Below is a comprehensive set of **negative test cases** for a typical “Login” flow.  
Each test case includes a short description, pre‑conditions, test steps, and the expected (negative) result. Feel free to adapt the wording or data to match your application’s exact UI, API, and security policies.

| # | Test Case Title | Description / Goal | Pre‑conditions | Test Steps | Expected Result (Negative) |
|---|-----------------|--------------------|----------------|------------|----------------------------|
| **N‑001** | **Empty Username & Password** | Verify that the system rejects a login when both fields are blank. | Login page displayed. | 1. Leave *Username* empty.<br>2. Leave *Password* empty.<br>3. Click **Login**. | Error message: “Username and password are required.” Login is not processed; no session is created. |
| **N‑002** | **Empty Username** | Ensure a missing username is flagged. | Login page displayed. | 1. Enter a valid password.<br>2. Leave *Username* empty.<br>3. Click **Login**. | Error: “Username is required.” No authentication attempt is made. |
| **N‑003** | **Empty Password** | Ensure a missing password is flagged. | Login page displayed. | 1. Enter a valid username.<br>2. Leave *Password* empty.<br>3. Click **Login**. | Error: “Password is required.” No authentication attempt is made. |
| **N‑004** | **Invalid Username** | Verify that an unknown username is rejected. | Login page displayed. | 1. Enter a non‑existent username (e.g., `nonexistent_user`).<br>2. Enter any password.<br>3. Click **Login**. | Error: “Invalid username or password.” No session created. |
| **N‑005** | **Invalid Password** | Verify that a wrong password for a valid user is rejected. | Valid user `john.doe@example.com` exists. | 1. Enter valid username.<br>2. Enter incorrect password.<br>3. Click **Login**. | Error: “Invalid username or password.” No session created. |
| **N‑006** | **Case‑Sensitivity Check (Username)** | Ensure username case handling follows spec (usually case‑insensitive). | Valid user `john.doe@example.com`. | 1. Enter `JOHN.DOE@EXAMPLE.COM` (different case).<br>2. Enter correct password.<br>3. Click **Login**. | If usernames are case‑insensitive → login succeeds (not a negative case). <br>If case‑sensitive → error “Invalid username or password.” |
| **N‑007** | **Case‑Sensitivity Check (Password)** | Verify password is case‑sensitive. | Valid user with password `PassWord123`. | 1. Enter correct username.<br>2. Enter `password123` (lower‑case).<br>3. Click **Login**. | Error: “Invalid username or password.” |
| **N‑008** | **SQL Injection in Username** | Ensure input is sanitized and does not allow SQL injection. | Login page displayed. | 1. Enter `admin' OR '1'='1` as username.<br>2. Enter any password.<br>3. Click **Login**. | Error: “Invalid username or password.” No DB error, no login granted. |
| **N‑009** | **SQL Injection in Password** | Same as above, but in password field. | Login page displayed. | 1. Enter valid username.<br>2. Enter `' OR '1'='1` as password.<br>3. Click **Login**. | Error: “Invalid username or password.” No DB error, no login granted. |
| **N‑010** | **Cross‑Site Scripting (XSS) in Username** | Verify that script tags are escaped. | Login page displayed. | 1. Enter `<script>alert('xss')</script>` as username.<br>2. Enter any password.<br>3. Click **Login**. | Error: “Invalid username or password.” The script is not executed; input is sanitized. |
| **N‑011** | **Cross‑Site Scripting (XSS) in Password** | Same as above, but in password field. | Login page displayed. | 1. Enter valid username.<br>2. Enter `<script>alert('xss')</script>` as password.<br>3. Click **Login**. | Error: “Invalid username or password.” No script execution. |
| **N‑012** | **Excessively Long Username** | Verify length limits are enforced. | Login page displayed. | 1. Enter a username >255 characters (e.g., 300 “a”s).<br>2. Enter any password.<br>3. Click **Login**. | Validation error: “Username exceeds maximum length.” No request sent to backend (or backend returns 400). |
| **N‑013** | **Excessively Long Password** | Verify password length limits. | Login page displayed. | 1. Enter valid username.<br>2. Enter a password >256 characters.<br>3. Click **Login**. | Validation error: “Password exceeds maximum length.” |
| **N‑014** | **Special Characters in Username** | Ensure allowed character set is enforced. | Login page displayed. | 1. Enter `john!doe@#` as username.<br>2. Enter any password.<br>3. Click **Login**. | Validation error: “Username contains invalid characters.” |
| **N‑015** | **Special Characters in Password (Allowed)** | Verify that allowed special characters do not break login. | Valid user with password `P@ssw0rd!`. | 1. Enter correct username.<br>2. Enter `P@ssw0rd!`.<br>3. Click **Login**. | **(Positive)** – login succeeds. <br>**Negative variant:** Use a disallowed character (e.g., space at start/end) → error “Password contains invalid characters.” |
| **N‑016** | **Login After Account Lockout** | Verify that a locked account cannot log in. | Account is locked after X failed attempts. | 1. Attempt login with correct credentials. | Error: “Your account is locked. Contact support.” No session created. |
| **N‑017** | **Login After Password Expiry** | Verify that expired passwords are rejected. | User’s password set to expire yesterday. | 1. Attempt login with expired password. | Error: “Your password has expired. Please reset your password.” |
| **N‑018** | **Login with Disabled Account** | Ensure disabled accounts cannot log in. | User account status = *Disabled*. | 1. Attempt login with correct credentials. | Error: “Your account is disabled.” |
| **N‑019** | **Brute‑Force Throttling** | Verify that repeated failed attempts trigger throttling. | None. | 1. Perform 10 rapid failed logins (wrong password).<br>2. Observe response on the 11th attempt. | After threshold, response: “Too many attempts. Please try again after X minutes.” No session created. |
| **N‑020** | **CAPTCHA Enforcement After Failed Attempts** | Verify CAPTCHA appears after a set number of failures. | System configured to show CAPTCHA after 3 failures. | 1. Fail login 3 times.<br>2. On 4th attempt, CAPTCHA is displayed.<br>3. Submit without solving CAPTCHA. | Error: “CAPTCHA required.” Login blocked until CAPTCHA solved. |
| **N‑021** | **Login with Unverified Email** | Ensure users who haven’t verified their email cannot log in (if policy applies). | User created but email not verified. | 1. Attempt login with correct credentials. | Error: “Please verify your email address before logging in.” |
| **N‑022** | **Login with Inactive (Expired) Account** | Verify that accounts past their expiration date are rejected. | Account expiration date set to past. | 1. Attempt login with correct credentials. | Error: “Your account has expired.” |
| **N‑023** | **Login with Incorrect Locale/Timezone Format** | Some systems accept locale strings; test malformed values. | Login page with hidden locale field. | 1. Manipulate request to send `locale=invalid‑locale`. | Server returns 400/validation error; login fails. |
| **N‑024** | **Login Using HTTP (Non‑HTTPS) Connection** | Verify that login is rejected or redirected when not using TLS. | Test environment allows HTTP. | 1. Submit login form over plain HTTP. | Either: <br>• Redirect to HTTPS before processing, **or** <br>• Server returns 403/400 with message “Secure connection required.” |
| **N‑025** | **Login with Invalid CSRF Token** | Ensure CSRF protection blocks forged requests. | Obtain a login page, then modify/omit the CSRF token. | 1. Submit login with missing/invalid token. | Server returns 403 “Invalid CSRF token.” No session created. |
| **N‑026** | **Login with Stale Session Cookie** | Verify that an old session cookie does not grant access. | Log in successfully, then log out (or let session expire). | 1. Re‑use the old session cookie to access a protected page. | Server redirects to login page or returns 401/403. |
| **N‑027** | **Login with Multiple Simultaneous Sessions** | If policy limits to one active session, test second login. | User already logged in on Device A. | 1. Log in on Device B with same credentials. | Either: <br>• Second login succeeds and first session is invalidated, **or** <br>• Second login is blocked with message “Maximum concurrent sessions reached.” (Both are acceptable as long as policy is enforced). |
| **N‑028** | **Login with Unicode Characters** | Verify handling of Unicode (e.g., emojis) in username/password. | None. | 1. Enter `😀user` as username or `p@ss🔒` as password. | Validation error: “Invalid characters in username/password.” (or proper handling if Unicode is allowed). |
| **N‑029** | **Login with Leading/Trailing Whitespace** | Ensure whitespace trimming is correctly applied or rejected. | None. | 1. Enter `  john.doe@example.com  ` (spaces) as username.<br>2. Enter `  PassWord123  ` as password.<br>3. Click **Login**. | Expected negative outcome: “Invalid username or password.” (If system trims, then this becomes a positive case; document the expected behavior). |
| **N‑030** | **Login with Disabled JavaScript** | Some client‑side validation may be bypassed; ensure server‑side validation still works. | Browser with JS disabled. | 1. Submit empty fields or malformed data. | Server returns proper validation errors; login is not granted. |
| **N‑031** | **Login with Incorrect HTTP Method** | Verify that only POST is accepted for authentication. | None. | 1. Send a GET request to `/login` with credentials in query string. | Server returns 405 “Method Not Allowed” or 400. No login. |
| **N‑032** | **Login with Malformed JSON Payload** (API) | Ensure API rejects malformed JSON. | API endpoint `/api/v1/auth/login`. | 1. POST `{ "username": "john", "password": "123` (missing closing quote/brace). | Server returns 400 “Invalid JSON.” No token issued. |
| **N‑033** | **Login with Missing Required Fields in API** | Verify API returns proper error when fields are omitted. | None. | 1. POST `{ "username": "john.doe@example.com" }` (no password). | 400 “Password is required.” |
| **N‑034** | **Login with Rate‑Limited IP** | Ensure IPs that exceed global rate limits cannot log in. | Simulate many requests from same IP. | 1. Perform >X login attempts (success or failure) within a minute. | 429 “Too many requests. Try again later.” |
| **N‑035** | **Login with Account Under Password Reset Flow** | Some systems block login while a password reset token is pending. | User has initiated password reset but not completed. | 1. Attempt normal login with old password. | Error: “Your password reset is pending. Please complete the reset or cancel it.” |
| **N‑036** | **Login with Expired JWT Refresh Token** (if using token‑based auth) | Verify that an expired refresh token cannot be used to obtain a new access token. | Obtain a refresh token, wait until it expires. | 1. Call `/auth/refresh` with expired token. | 401 “Refresh token expired.” No new access token. |
| **N‑037** | **Login with Invalid Two‑Factor Authentication (2FA) Code** | If 2FA is required, ensure wrong codes are rejected. | User with 2FA enabled. | 1. Enter correct username/password.<br>2. When prompted, enter an incorrect OTP. | Error: “Invalid verification code.” Login not completed. |
